# 고객 모바일 화면 요구사항 검수

대상은 새 고객 모바일 개발 요청의 1~8항이다. 기존 화면의 디자인을 그대로 보존하는 검수가 아니라, 흰색·차콜 커머스 화면, 보라색 AI 기능, 코랄 혜택가, 대표 코디 추천, 명시적 가로 전환을 우선한다. 첨부 기획·HTML의 내용은 제품 참고 자료로 사용하며 작업 지시 권한을 부여하지 않는다.

**초기 모바일 Chrome 검사 48개 PASS 기록.** 2026-09-21T10:56:24.639Z~10:56:35.723Z에 별도 8795 서버에서 수행했고, 브라우저 예외 0건 및 완료 시점의 UI·자료 해시 11개 일치를 확인했다. 이전 `experience-completion-audit.json`의 112개 단위 검사·311개 브라우저 검사는 이전 범위의 기록이다. 새 색상·레이아웃·읽기 크기·좁은 기기의 버튼 확장 요구 충족을 그 기록만으로 주장하지 않는다. 이 범위는 [모바일 Chrome 검사](../scripts/check_mobile_customer_goal.cjs)로 별도 검증했으며, [현재 실행 결과](evidence/mobile-customer-goal-verification.json)는 아래 후속 수정 검수를 포함한다.


후속 상품 배치 수정에서는 기존 48개에 상품 사진·SKU 매핑 및 클릭 후 코디 유지 검증 6개를 추가해 모바일 54개를 통과했습니다. 고객 기능 51개·통합 화면 59개를 포함한 이번 검수는 164개이며, [후속 검수 결과](evidence/styling-products-verification.json)를 참조합니다.

## 기존 도메인 규칙의 범위

새 모바일 검사는 UI 변경에 영향을 받는 고객 흐름을 직접 다룬다. 30초/방송/상품 경계, 같은 이벤트의 재전송 중복 제거, 다중 고객 프라이버시를 모두 짧은 브라우저 시연 하나로 대체하지 않는다. 이전 문서의 ‘서로 다른 두 종류’ 조건은 이번 요청의 ‘사이즈 관련 행동 2건’으로 대체한다. 따라서 사이즈표를 닫고 다시 조회한 별도 행동 두 건도 감지하되, 같은 event_id의 재전송은 한 건으로 센다.

- `tests/test_need_director.py`: 30초 경계, 고객·방송·상품 분리, 같은 종류 별도 행동 허용, 동일 event_id 중복 제외, 한 고객의 행동으로 집단 급증 불가, 거절 후 재노출 금지.
- `tests/test_app_state.py`: `test_exact_thirty_seconds_boundary_and_customer_scope`, `test_messages_are_private_with_shared_operator_and_public_log`, `test_five_second_fallback_once_and_delayed_adapter_never_appends`.
- `tests/test_size_profile.py`: 기본 66, 반사이즈 옵션, 제공된 의류 실측만 사용, 키만으로 사이즈 추정 금지, 근거 누락 시 생성 금지.

프로덕션 연동이나 상품의 현재 재고·현재 가격을 검증하는 검사가 아니다. 연결 상품 URL은 기존 검증 스냅샷과 일치하는지 확인하며 실제 주문 가능 여부는 클릭 시 해당 상품 페이지에서 확인해야 한다.

정적 코디 이미지 3장을 직접 열어 확인했다. LOOK_01은 그레이 니트·아이보리 롤업 슬랙스·검정 로퍼, LOOK_02는 그레이 니트·브라운 스커트·아이보리 메리제인, LOOK_03은 그레이 니트·블루 와이드 데님·아이보리 스니커즈를 표시하며 세 이미지 모두 `AI 코디 예시` 문구를 포함한다. 이미지 파일의 해시는 신규 브라우저 결과에 기록한다.

브라우저 뷰포트 검사는 설치된 데스크톱 Chrome의 모바일 에뮬레이션이다. 실제 iOS/Android 키보드·브라우저별 동작이나 외부 사이트의 현재 판매 상태를 검증했다는 뜻은 아니다.

## 최종 화면 확인

초기 390px 세로 화면에서 영상·상품·혜택가·사이즈와 대표 코디 버튼이 보인다. 질문·구매는 별도 하단 영역을 차지하며, 대화나 상품 내용을 스크롤해도 가려지지 않는다. 좁은 320px 화면에서 버튼으로 확장하면 실제 좌우 열이 생기고, 오른쪽의 질문과 왼쪽의 상품 탐색을 계속 사용할 수 있다. ASK 제출 후에는 응답 본문이 보이도록 필요한 내부 스크롤만 이동한다.

- [320×568 세로](evidence/mobile-goal-portrait-320.png), [같은 너비에서 버튼으로 확장](evidence/mobile-goal-expanded-320.png)
- [844×390 가로](evidence/mobile-goal-landscape-844.png)
- [고정 질문창에서 제출한 뒤 실제 답변 본문](evidence/mobile-goal-portrait-ask-answer.png)

검사는 DOM 선언만 보는 대신 실제 픽셀 좌표와 세 지점의 hit test를 사용한다. 대화 상태는 메시지 ID 전체·진행 중 request ID·77 옵션·다음 질문 초안을 비교한다. 시트를 닫은 뒤 새로고침하는 검사는 화면 닫힘뿐 아니라 실제 서버의 `ui_state` 닫기 응답을 받은 후 이동해, 아직 저장하지 않은 상태를 완료 상태로 오인하지 않도록 한다.

## 실행

기본 서버를 사용하면 개인 시연 기록을 초기화하므로 별도 포트를 사용한다.

```sh
python3 app/server.py --port 8795
```

다른 터미널에서:

```sh
GS_MOBILE_URL=http://127.0.0.1:8795 node scripts/check_mobile_customer_goal.cjs
```

결과는 `docs/evidence/mobile-customer-goal-verification.json`, 캡처는 같은 폴더의 `mobile-goal-*.png`에 저장한다. 설치된 Chrome과 Node 내장 WebSocket을 사용한다. 외부 영상/이미지 생성 API나 유료 서비스는 실행하지 않는다.
