# Director 전체 구좌 데이터 연동 점검

2026-09-21 최종 갱신. 요청: “실시간 모니터링 대시보드 구좌들 고객 화면 데이터와 연동 되었는지 실시간 모니터링 부터 효과분석까지 확인해줘”. 실제 코드·공개 API·서로 다른 Chrome 페이지의 고객 조작을 기준으로 확인했다. 신규 관심 통계·공개 댓글·구매 체험 완료율·개인 프로필까지 포함한 최종 범위에서 구좌별 고객 데이터 연동 누락은 발견하지 않았다. 고정 예시와 실제 수신값은 아래처럼 구분한다.

## 갱신 방식

고객 조작 → `/api/action` → 서버의 현재 방송·상품 상태 → Director `/api/state` 조회 → 구좌 표시 순서다. 조회 간격은 500ms이며 서버 처리·네트워크 시간은 별도다. 접속 신호는 5초, 만료는 마지막 신호 후 15초다. Need 집단 분석은 매 클릭이 아니라 60초마다 수행한다. 시연 모드의 가상 시계는 직접 진행한다.

신규 관심 통계의 `received_at`/`as_of`는 실행 시작 이후 **실제 서버 수신 경과초**다. 최근 5분·30분 통계는 이 시계로 계산하며, LIVE/Need 분석/승인 TTL의 도메인 시계와 구분한다. Demo Control로 가상 시간을 이동해도 실제 질문이 그만큼 오래된 질문으로 바뀌지 않는다.

고객 개인 질문·답변·프로필 원문은 Director에 전달하지 않는다. 분류·행동·허용된 선택값과 가상 고객 A/B/C ID만 사용한다. 화면에 고정 규칙·질문 예시·상품 스냅샷·성과 Simulation이 함께 있으므로 아래에서 원천을 구분한다.

## 실시간 모니터링 및 공통 구좌

| 구좌 | 실제 원천 | 반영 방식·한계 |
| --- | --- | --- |
| 상품명·상품번호·가격·리뷰·썸네일 | `/api/bootstrap.product` | 고정 상품 스냅샷. 고객 클릭으로 바뀌는 수치가 아님 |
| LIVE 시계·RUN·방송 ID | `now`, `run_id`, `scope.broadcast_id` | 자유 체험은 서버 시계, Demo Control은 가상 시계 |
| Need 감지 고객 | `counts.detected` | 현재 방송·상품의 고유 감지 고객. 다른 상품 감지는 제외 |
| 처리된 행동 | `counts.events` | 현재 방송·상품의 UI+Fixture 이벤트, 중복 ID 제외 |
| 고객 UI 행동 / 시연 행동 | `counts.ui_events / fixture_events` | 실제 화면에서 받은 행동과 준비 재생을 구분 |
| 접속 고객·탭 | `integration.presence` | 실제 heartbeat. 동일 고객의 여러 탭을 고객 수와 분리 |
| 실제 질문·공용 안내 요약 | `integration.totals.asks`, 활성 `notices` | 고객 ASK 제출과 Director 안내 게시/회수에 따라 갱신 |
| 실시간 고객 현황의 시청 고객 | `integration.monitor.viewers` | 현재 접속 고유 고객·탭과 이번 실행의 고유 LIVE 입장 고객. 이미지 예시 시청자 수는 사용하지 않음 |
| 공개 댓글 수·최근 댓글 | `integration.monitor.comments.total`, `integration.comments` | 별도 공개 입력으로 게시한 댓글의 누적 건수와 최근 목록. 개인 ASK는 댓글로 재사용하지 않으며 HTML은 텍스트로 표시 |
| 구매 체험 완료율 | `integration.monitor.conversion` | 고유 LIVE 입장 고객 중 완료 체험 고객의 비율. 중복 완료는 고객별 한 번, 입장 고객 0명은 `—`. 실제 결제·매출 전환율이 아님 |
| 관심 분류 시계열·범례 | `integration.monitor.trend` | 사이즈/가격·혜택/배송/상품 정보/기타 5분류, 최근 30분·1분 구간. 한 질문의 같은 분류는 한 번만 집계하며 범례로 표시 여부를 바꿈 |
| 현재 주요 질문 TOP 5 | `integration.monitor.top_questions` | 최근 30분 실제 요청의 안전한 topic ID를 고정 대표 문구로 표시. 실제 건수와 순위이며 개인 질문 원문이나 고정 예시 건수가 아님 |
| 최근 5분 주요 관심·인사이트 | `integration.monitor.insight` | 최근 5분과 직전 5분의 같은 분류 건수·증감. 직전 0건은 무한 증가율 대신 신규 관심, 수신 없음은 대기. 별도 LLM 호출이 아닌 집계 설명 |
| OBSERVE → DETECT → ACT → MEASURE | `campaign.state` | 조건 충족·승인·Show Result에 따라 서버가 전환 |
| 사이즈 관심 차트·증감·기간 | `campaign.evidence` | 60초 구간별 신규 감지 고객. ALERT 뒤에는 해당 급증 근거를 고정 표시 |
| 다음 분석 안내 | `next_analysis_at - now`, `mode` | 다음 분석까지 남은 시간. 시연 모드는 시계 진행 필요 |
| 감지 근거 2종/30초/2배/10명 | 확정 도메인 규칙 | 설명용 고정값. 현재 고객 행동 횟수가 아님 |
| 감지 근거 아래 질문 예시 | HTML의 명시된 Fixture 문구 | 고객 질문 원문이 아님. 고정 예시이며 위의 실제 TOP 5와 별도 |
| 기존 Need AI INSIGHT | 단계·감지 인원·승인 인원을 넣은 준비 문구 | 규칙 기반 서버 상태 설명. 신규 최근 5분 질문 인사이트와 별도이며 LLM 분석을 호출하지 않음 |
| 추천 대응안·승인 가능 인원 | `campaign`, `approval_preview` | 최근 120초 감지·거절·상품 전환을 반영한 실제 대상 |
| APP 대상·제외 사유·미리보기 | `customers`, 승인 snapshot | 승인 당시 대상 고정, 300초 만료·거절·전환·종료 반영 |
| 쇼호스트 안내 검토·전달 | `host_text`, `host_delivered` | 수정·확인 후 로컬 완료 기록. 외부 송출 없음 |
| 연결된 고객 화면 | `customers + integration.customers` | 실제 접속·현재 화면·선택·코디·미디어·최근 행동·Need·승인 연결 |
| 실제 이용·효과 분석 진입 | 현재 연결 상태 | 고정 성과 공개 전에도 실제 누적 집계 확인 가능 |

허용 고객 A/B/C는 3명이다. 실제 클릭만으로 개인 Need는 확인할 수 있지만, 고유 고객 10명이 필요한 집단 급증은 준비된 고객 이벤트를 추가 재생해야 한다. 같은 고객의 반복 클릭을 신규 고객으로 늘리지 않는다.

## 고객 이용 · 안내

| 구좌 | 원천 및 검수 기준 |
| --- | --- |
| 실제 이용 카드 10개 | `integration.totals`: 전체 행동·고유 고객·질문·사이즈·혜택·코디·상세·구매 진입·구매 체험 완료·미디어 오류. 현재 상품 UI만 포함 |
| 질문 유형 | `integration.intents`: 서버 분류 요청 수. 복합 질문은 최대 두 분류에 각각 포함 |
| 답변 처리 상태 | `integration.response`: 처리 중·완료·대체·취소. 대체는 완료의 부분집합 |
| 공용 안내 작성·목록·회수 | `notices`: 실제 Director 입력과 상태. 동일 ID 재시도 중복 방지 |
| 표시 고객 수 | 고객 화면의 `notice_seen` 확인 | 
| 고객별 현재 이용 상태 | `integration.customers`: 모니터 표와 동일한 원천 |
| 컬러·사이즈·Look 분포 | `selections`: 실제 변경만 집계. 기본값과 같은 선택 반복은 제외 |
| 연결 상품 클릭 | `linked_products`: 코디의 실제 상품 ID별 클릭 수 |
| 행동별 건수 | `event_counts`: 같은 실행·상품 UI 이벤트의 종류별 수 |
| 최근 고객 행동 | `recent`: 서버 수신 순서 역순, 최대 50건 |

연결이 끊기면 공통 접속 요약과 두 고객 표 모두 ‘확인 중’으로 바뀐다. 이용 수치는 마지막 수신값임을 안내한다. 시연 시간이 멈춰 같은 JSON을 다시 받더라도 재연결 시 표시를 복구한다.

장바구니·공개 댓글·공유·전체 코디·장면 이동·개인 프로필 저장도 허용된 실제 행동으로 집계한다. `PROFILE_UPDATE`는 저장 행동만 공개하며 입력한 키·평소 사이즈·보유 의류 치수·개별 추천을 전송하지 않는다. 따라서 저장으로 전체 행동 건수와 참여 고객 분모는 늘 수 있지만 질문·시청자·Need를 임의로 만들지 않는다. ASK 직후 자동 AI 제안이 표시되면 최신 행동은 `AI_SUGGESTION_SHOWN`이 될 수 있으며 ASK 수신 건수는 그대로 유지된다.

## 액션 기록

| 구좌 | 원천 및 검수 기준 |
| --- | --- |
| 메뉴 배지 / 목록 건수 | 같은 `logs`의 최근 최대 300건. 승인 두 건만 세던 불일치 수정 |
| 기록 순서 | 서버 `sequence`에 해당하는 수신 순서의 역순. 같은 가상 시각에서도 최근 행동이 먼저 표시 |
| 고객 행동 상세 | 가상 고객 ID·상품 ID·이벤트 종류·분류·허용된 옵션/코디/탭 메타데이터 |
| 분석 상세 | 이전/현재 구간 인원과 급증 충족 여부 |
| APP 승인 상세 | 승인 대상 수·강조 만료 시각 |
| 실제 APP 노출 | 현재 승인 ID의 대상 고객이 보낸 `PERSONALIZATION_SHOWN`. 중복 수신은 실제 노출 고객 수를 늘리지 않음 |
| 시계·안내·상품 전환 상세 | 진행한 초, 안내 ID, 이전/이후 상품과 가상 고객 |
| 출처 | 고객 UI / 시연 Fixture / PD 액션 / 시연 제어 / 서버 |

Size Need 엔진에서 신호로 취급하지 않는 정상 혜택·옵션 행동도 이용 기록에는 포함한다. 이 경우 원시 `IGNORED` 대신 이용 기록 완료를 표시한다. 실제로 수락할 제안이 없는 요청은 조건 불충족으로 구분한다. 기록은 실행 전체를 보여주므로 다른 상품 기록도 상품 ID와 함께 남으며, 메인 상품 KPI에는 합산하지 않는다.

실제 전후 값은 승인 당시 활동 목록의 수신 위치를 기준으로 나누며, 누적 관찰 기간이 다르므로 동일 기간 비교·인과적 개선 효과·실제 결제 전환율·매출로 해석하지 않는다. 새 3개 실제 지표와 기존 4행 실제 이용 표를 모두 유지한다. 상단 완료율의 분모는 LIVE 입장 고객이고, 전후 완료율의 분모는 **각 구간에서 행동한 고객**이므로 두 비율의 모집단도 다르다. 고정 성과 카드는 기존 명세의 시연 결과를 유지하며, 공개해도 실제 집계 표나 새 지표를 덮어쓰지 않는다.

## 발견 후 수정한 사항

1. 다른 상품의 행동·Need가 상단 메인 상품 KPI에 포함되던 범위 오류.
2. 고정 시연 상태에서 재연결했을 때 ‘확인 중’이 남던 렌더링 오류.
3. 액션 기록 메뉴가 승인 수만 세고, 분석·승인·시계 진행 상세를 누락하던 문제.
4. 같은 가상 시각의 기록을 오래된 수신 순으로 보여주던 정렬 문제.
5. 실제 분석 표가 있는데도 고정 성과 공개 전에는 분석 진입 버튼을 막던 문제.
6. 고정 성과가 자동 공개되는 것처럼 안내하던 문구 및 차트 갱신·가상 고객 수 설명 부족.
