# GS AI LIVE 실행·시연

Python 3.9 이상으로 로컬에서 실행한다. 패키지 설치·API 키·네트워크 연결 없이 상품·리뷰·코디·참고 영상과 전체 시연을 사용할 수 있다. 실제 상품 링크를 열 때만 외부 사이트로 이동한다.

```sh
cd /Users/yeongjae/Desktop/aidlc-v1-sample-project
python3 app/server.py
```

macOS에서는 `scripts/run_demo.command`를 실행해도 된다. 서버 종료는 실행한 터미널에서 Ctrl+C다. 포트를 바꾸려면 `python3 app/server.py --port 8770`으로 실행한다. 프로세스 종료 시 가상 고객의 실행 상태는 사라진다.

- 고객 A: http://127.0.0.1:8765/app/customer.html?customer=customer-A
- 고객 B: http://127.0.0.1:8765/app/customer.html?customer=customer-B
- 고객 C: http://127.0.0.1:8765/app/customer.html?customer=customer-C
- Director: http://127.0.0.1:8765/app/director.html

같은 서버를 사용해야 상태가 연결된다. HTML을 파일로 직접 열면 API를 사용할 수 없다. 기본 시연은 같은 기기의 여러 탭/창이며 localhost 전용이다. 고객 선택은 가상 고객 체험 도구로 실제 인증을 구현한 것이 아니다.

## 고객 체험

1. 후기·두께·색상·배송 질문을 입력한다. 답변 안의 리뷰 막대와 전체 리뷰 버튼, 준비된 데이터의 근거와 라벨을 확인한다. 고객 질문과 답변은 해당 가상 고객에게만 보이고 운영자 메시지는 공용이다.
2. `내 사이즈`에서 평소 사이즈·반사이즈 여부·선호 핏과 선택 입력인 키·보유 상의 가슴단면을 넣고 `내 기준 저장 · 추천 확인`을 누른다. 의류를 평평하게 놓고 잰 폭을 입력하며 신체 가슴둘레를 넣지 않는다. 기본 추천은 66이고 입력 조건에 따라 실측 비교 사유를 표시한다. 추천은 구매 옵션을 자동 변경하지 않으므로 원하는 사이즈를 직접 선택한다. 87%는 유사 체형 만족률이 아닌 전체 선택형 리뷰 집계다. `내 혜택`에서 45,515원 계산과 GS Pay·할부·배송 조건을 확인한다. 그레이 66은 확인 당시 일시품절이다.
3. `코디 추천`의 오피스·데이트·데일리 탭으로 큰 AI 코디 예시를 전환한다. 오른쪽에는 선택 코디의 실제 상의·하의·신발 사진이 표시되며 각 사진을 누르면 해당 상품 상세가 열린다. 전체 상품 보기에서는 확정 7개 SKU를 확인한다.
4. 사이즈표를 열고 30초 안에 사이즈 리뷰를 확인한 뒤 시트를 닫으면 개인 제안이 나타난다. 확인하기/괜찮아요 중 선택한다. Director 고객 상태 표에서도 실제 클릭에 따른 감지를 확인할 수 있다.
5. 공유 아이콘으로 공개 상품 링크를 복사한다. 복사 권한이 없으면 선택된 주소를 직접 복사한다. 개인 대화와 장바구니는 공유 링크에 포함되지 않는다.
6. 옵션 선택 후 장바구니에 담고 수량 변경·삭제·상품별 구매 체험을 수행한다. 옵션당 최대 10개이며 상품가 49,900원×수량과 준비 혜택가 45,515원×수량을 구분한다. 실제 주문은 생성되지 않는다.
7. `공개 댓글`을 펼쳐 글을 게시하면 다른 고객의 방송 위 최근 댓글과 Director에 표시된다. 개인 ASK 입력은 공개하지 않는다.
8. 영상 위 나가기 버튼은 해당 탭의 접속만 종료한다. 다른 탭과 방송은 유지하며 재입장 시 저장한 옵션·장바구니를 다시 볼 수 있다. 세로/가로 변경과 결과 시트도 계속 사용할 수 있다.

## 고객 · Director 양방향 연동 체험

Director의 **고객 이용** 메뉴를 열고 고객 A/B/C를 별도 탭으로 연다. 현재 접속은 실제 열린 고객 탭의 신호로 표시하며 같은 고객의 여러 탭은 고객 한 명과 여러 세션으로 구분한다. 끊긴 연결은 최대 15초 뒤 집계에서 빠진다.

기본 **실시간 모니터링 → 연결된 고객 화면** 표에서도 접속·현재 화면·선택 옵션·코디·최근 행동을 바로 확인할 수 있다. ‘내 사이즈’ 버튼을 누르면 해당 이용 상태가 바뀐다. SIZE Need 감지는 사이즈표·사이즈 리뷰·사이즈 질문 행동이 30초 안에 2건 발생해야 하므로 일반 이용과 구분한다.

1. 고객 화면에서 질문, 사이즈·혜택·코디 결과, 상세/리뷰/문의 탭, 옵션/Look 변경, 연결 상품 클릭, 구매 체험을 수행한다.
2. Director의 실제 이용 카드·질문 유형·선택 분포·고객별 현재 화면·최근 행동을 확인한다. 실시간 모니터에는 공개 댓글 수, 고유 방문 고객 중 구매 체험 완료율, 5개 관심 분류의 최근 30분 트렌드와 주요 질문 TOP 5도 표시된다. 개인 질문 원문과 개인 답변은 노출하지 않는다. 분포는 변경 횟수이며 기본 선택값은 포함하지 않는다.
3. **고객에게 공용 안내**에서 문구와 연결 버튼을 선택하고 게시한다. 모든 고객 대화에 공용 안내가 나타나며 버튼을 누르면 해당 정보로 이동한다. 표시 고객 수는 실제 화면에 노출된 고객 수로, 읽거나 이해했다는 뜻은 아니다.
4. **안내 회수**로 모든 고객 화면에서 안내를 제거한다. 게시·회수 이력은 Director에 유지되며 Reset으로 초기화된다.
5. APP 승인 전후로 질문·사이즈 보기·구매 체험을 추가한 뒤 효과 분석의 실제 누적 건수를 확인한다. 아래 고정 Simulation과 별도이며 관찰 시간이 다르므로 개선 효과나 전환율로 해석하지 않는다.

새로고침·다른 탭 입장·일시 연결 실패 후에는 현재 서버 실행에 다시 연결한다. Reset은 안내·대화·선택·실제 집계도 초기화하고 열린 고객 탭은 새 실행에 재접속한다. 방송 종료는 추천을 해제하고 질문·새 공용 안내를 막으며 수동 정보 탐색은 유지한다.

모니터의 누적 Need 감지 고객은 조작 후 갱신되지만, 사이즈 관심 차트는 60초 분석 주기에 갱신된다. 시연 모드는 가상 시계를 진행해야 하며 급증 뒤 차트는 급증 당시 근거를 유지한다. A/B/C 세 고객만으로 개인 Need는 확인할 수 있지만, 고유 고객 10명이 필요한 급증 시연에는 아래 준비 이벤트를 사용한다. 효과 분석의 실제 집계는 APP 승인 전부터 확인할 수 있다.

최근 5분 인사이트와 관심 트렌드는 실제 서버 수신 경과초를 사용한다. Demo Control의 가상 시계를 진행하거나 영상을 탐색해도 이 시간 창은 바뀌지 않는다. 액션 현황의 승인 대상 수와 실제 버튼 표시 확인 고객 수를 구분한다. 추가 전후 지표는 사이즈 질문·상품 상세 조회·구간 참여 고객 중 구매 체험 완료율이며 실제 주문 전환율을 뜻하지 않는다.

자세한 이벤트·집계·노출 기준은 [연동 계약](cross-screen-contract.md), 구좌별 실제 원천과 고정값 구분은 [Director 데이터 점검표](director-data-audit.md)를 참고한다.

## 8→26 → 승인 → 결과 재현

Director 하단의 `개발자용 Demo Control`을 사용한다. 고객 A/B/C를 별도 탭으로 열어두면 비교하기 쉽다.

| 순서 | 조작 | 확인 |
| --- | --- | --- |
| 1 | Reset | 이전 이벤트·대화·거절·승인·요청·시계 초기화 |
| 2 | Start Need Demo | 새 실행에서 68초까지 재생. A 제안, C 거절 |
| 3 | 고객 A 확인하기 → 결과 닫기 | 수락 후 사이즈 결과 표시. 수락으로 감지 인원을 늘리지 않음 |
| 4 | Trigger Director Spike | 남은 이벤트만 120초까지 재생. 8→26명(+225%) ALERT |
| 5 | 쇼호스트 안내 검토·수정·확인 | 로컬 전달 완료. APP 개인화와 독립 |
| 6 | APP 개인화 검토 → 승인하고 적용 | 121초 대상 33명 고정. A 추천 강조, B/C 기본 버튼 |
| 7 | Show Result | 가상 시계 151초. 질문 26→11, 사이즈 이용 14→43, 구매 클릭 82→95 |
| 8 | 강조 만료 | 가상 시계 421초, A 강조 해제 |

APP 승인은 실제 UI의 승인 버튼으로 실행한다. 개발자 컨트롤은 가상 시계를 진행하고 같은 도메인 로직에 이벤트를 공급한다. 쇼호스트 전달만으로 결과를 열 수 없다. 승인+30초로 시계만 진행해도 고정 결과는 자동 공개되지 않으며 `Show Result`를 눌러야 한다. 이 세 성과 KPI는 고정 `Prototype Simulation`이며 실제 사업 성과가 아니다. 정상 시연은 위 순서로 진행하고 자유 체험의 추가 이벤트는 Start에서 초기화한다.

## 참고 MP4

고객 화면의 `영상 선택`에서 `코어어센틱 녹화 참고 영상`을 선택하면 영상 위치로 이동한다. 이미지 모드에서는 `재생할 영상을 선택하세요`가 표시되어 같은 참고 영상을 다시 고를 수 있다. `방송 화면`의 `녹화 참고 영상` 전환도 계속 사용할 수 있다. 실제 재생 버튼을 눌러 소리를 켜거나 끄고 시점을 이동할 수 있다. 원본은 57.9초·9:16의 코어어센틱 가디건 영상으로 현재 SJ와니 상품과 다르다. 표시된 구분 문구를 유지한다. 영상 종료·되감기는 Need/승인 시계를 초기화하지 않는다.

영상 파일은 `assets/video/reference/core-authentic-cardigan.mp4`, 식별·검증 정보는 같은 폴더의 `manifest.json`이다. 앱이 프로젝트 내부 파일을 사용하므로 Downloads 원본이 없어도 재생한다. 참고 영상에서는 직접 확인한 화면 자막·모습 7개 구간의 장면 검색·요약·Catch-up·현재 장면 질문과 위치 이동을 사용할 수 있다. 검수 구간 밖이나 확인하지 않은 함량·착용 사이즈에는 확인 불가를 안내한다. 다른 상품의 영상 내용을 현재 상품 근거로 쓰지 않는다.

영상 선택에서 `상품 설명 샘플`로 바꾸면 기존 120초 영상의 제작 대본 12개 장면을 별도로 조회한다. 질문 답변의 장면 이동 버튼을 누른 뒤 원래 위치로 돌아가면 이전 영상·시각·재생/정지 상태를 복구한다. 샘플 대본 검색은 실제 방송 전사 결과가 아니다. 로컬 ASR 실행 결과는 오인식을 포함한 초안으로 보관하며 답변 근거에 자동 채택하지 않는다. 임의의 새 영상이나 실시간 방송 전체의 자동 분석은 검증하지 않았다. [기능·근거 범위](experience-extension.md#영상-근거)를 확인한다.

## 오류와 복구 체험

- 고객 화면 상단 `시연 설정`에서 ASK 응답 지연/오류를 선택한다. 지연은 5초 후 같은 Intent의 준비 답변으로 한 번 대체한다. Reset이나 상품 전환 후 늦은 응답은 이전 맥락에 머물거나 취소된다.
- 같은 메뉴에서 다른 상품으로 전환하면 기존 강조가 종료되며 복귀해도 자동 복구하지 않는다.
- 영상 오류 체험은 안내 후 실제 상품 이미지로 돌아간다. 파일/형식 문제의 실제 브라우저 검수는 아래 자동 검사에도 포함된다.
- 이미지 실패 시 실제 상품 카드·텍스트·링크로 대체한다. 서버가 끊기면 재연결 상태를 표시하며 서버를 재실행하면 새 실행으로 연결된다.

## 검증 명령

```sh
python3 scripts/validate_demo.py --write-report
python3 -m unittest discover -s tests -p 'test*.py' -v
python3 prototype/need_director.py
```

실제 앱의 브라우저 검사는 독립 서버를 실행한 뒤 별도 터미널에서 수행한다. 각 검사는 대상 서버의 데모 상태를 초기화하므로 사용자 화면이 열린 기본 8765 서버와 분리한다. Node 내장 WebSocket을 지원하는 버전과 설치된 Google Chrome이 필요하며 이번 환경은 Node 25.9.0을 사용했다. 기본 macOS Chrome 경로가 다르면 `CHROME_PATH`에 실제 실행 파일 경로를 지정한다. npm 설치는 필요 없다.

검사용 터미널에서 서버를 실행한다.

```sh
python3 app/server.py --port 8776
```

다른 터미널에서 여섯 검사를 하나씩 완료한 뒤 다음 검사를 실행한다. 같은 서버를 사용하는 검사를 병렬로 실행하면 서로 Reset하므로 결과를 신뢰할 수 없다.

```sh
GS_DEMO_URL=http://127.0.0.1:8776 node scripts/check_app_browser.cjs
GS_DEMO_URL=http://127.0.0.1:8776 node scripts/check_customer_context.cjs
GS_DEMO_URL=http://127.0.0.1:8776 node scripts/check_cross_screen.cjs
GS_DEMO_URL=http://127.0.0.1:8776 node scripts/check_connected_customers.cjs
GS_EDGE_URL=http://127.0.0.1:8776 node scripts/check_integration_edges.cjs
GS_DEMO_URL=http://127.0.0.1:8776 node scripts/check_dashboard_slots.cjs
```

`check_dashboard_slots.cjs`의 `GS_DEMO_URL` 기본값은 `http://127.0.0.1:8776`이며 실시간 모니터링부터 효과 분석까지 검사한다. 이 스크립트는 8765 포트의 초기화를 거부한다. 기본 모니터의 연결된 고객 표만 확인하려면 `check_connected_customers.cjs`를 실행한다. 해당 스크립트의 기본 포트는 8773이다. 예외 검사는 `GS_EDGE_URL`을 사용하며 기본 포트는 8772이므로 위처럼 검사 서버 주소를 명시하는 것이 좋다.

첨부 화면 기능의 신규 검사는 별도 서버를 사용한다. Customer와 영상 검사는 서버를 직접 실행한 다음 다른 터미널에서 검사한다.

```sh
# Customer 검사 서버
python3 app/server.py --port 8781
# 다른 터미널: 위 서버가 실행 중일 때
GS_EXPERIENCE_URL=http://127.0.0.1:8781 node scripts/check_customer_experience.cjs
```

```sh
# 영상 검사 서버
python3 app/server.py --port 8782
# 다른 터미널: 위 서버가 실행 중일 때
GS_VIDEO_URL=http://127.0.0.1:8782 node scripts/check_video_experience.cjs
```

사이즈 입력·실측 비교의 추가 검사는 8791 서버를 직접 실행한 뒤 별도 터미널에서 수행한다.

```sh
python3 app/server.py --port 8791
# 다른 터미널: 위 서버가 실행 중일 때
GS_SIZE_URL=http://127.0.0.1:8791 node scripts/check_size_profile.cjs
```

Director 신규 검사는 비어 있는 포트에서 자체 서버를 시작하고 종료한다. 별도 수신 시계를 사용해 5분·30분 경계를 검증하며 사용자 서버에 시험용 시간 API를 추가하지 않는다.

```sh
GS_EXPERIENCE_PORT=8788 node scripts/check_director_experience.cjs
```

신규 환경변수의 기본값은 위 주소·포트와 같다. 검사가 끝나면 직접 실행한 8781/8782/8791 서버는 Ctrl+C로 종료한다. 기본 8765 서버를 검사 대상으로 사용하지 않는다.

이전 통합 기능 확장 검수는 **Python 112개, 브라우저 311개** PASS 기록이다. 이후 모바일·코디·영상 선택 수정의 현재 검수는 [고객용 안내](mobile-customer-guide.md)를 참조한다. 기존 6종 194개(59+12+31+25+21+46)에 Customer 50개·Director 21개·영상 24개·개인 사이즈 입력 22개를 더한 수치다. 신규 보고서는 `customer-experience-verification.json`, `director-experience-verification.json`, `video-experience-verification.json`, `size-profile-verification.json`이다. 결과 JSON·화면 캡처는 `docs/evidence/`에 생성된다. 전체 구좌 보고서는 `dashboard-slots-verification.json`, 전체 페이지 이미지는 `dashboard-slots-*.png`다. 최종 항목별 판정과 남은 범위는 [앱 검수 결과](app-verification.md), [첨부 화면 구현 검토](experience-completion-review.md), [Director 데이터 점검표](director-data-audit.md)에서 확인한다.
