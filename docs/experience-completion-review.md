# 첨부 경험 화면 구현 검토

검토일: 2026-09-21. 대상은 첨부 `image-1.png`의 Customer Experience 5개 영역과 Director Experience 3개 영역이다. 이미지의 예시 숫자를 실제 데이터로 채택하지 않고, 기존 확정 상품·Need 규칙·Simulation과 충돌하지 않는 기능을 확인했다.

현재 코드, API 상태 구조, 검사 스크립트의 실제 assertion, 저장된 결과를 대조했다. 이 문서는 전체 제품·실운영 환경의 무조건적인 완료 인증이 아니다. 아래의 검증 범위와 미검증 범위를 함께 읽어야 한다.

## 이번 감사에서 발견하고 재검증한 문제

장바구니에서 2개를 구매 체험으로 넘긴 뒤 같은 고객의 다른 탭이 수량을 3개로 늘리면, 기존 완료 처리가 해당 행을 통째로 삭제했다. `app/state.py`에서 checkout 당시 수량을 보관하고 완료 시 그 수량만 차감하도록 수정됐다.

다음 두 검증을 직접 수행했다.

- `tests/test_customer_experience.py`의 `test_checkout_does_not_remove_quantity_added_from_another_tab`: 증가분 1개 보존 및 같은 완료 이벤트 재전송 시 추가 차감 없음.
- 별도 8789 서버의 실제 Chrome 두 탭: 블랙 66을 2개 담기 → 첫 탭 checkout → 둘째 탭에서 3개로 증가 → 첫 탭 완료. 서버 장바구니 잔량 **1개**, 완료 이벤트 **1건**, 브라우저 오류 **0건**. 이후 첫 탭 퇴장 시 두 번째 탭 **1세션/1고객** 유지, `ended=false` 확인.

이 다중 탭 감사는 별도 8789 서버에서 수행한 뒤 해당 서버를 종료했다. 모든 회귀 검사 후에는 8765 사용자 서버에도 최신 코드를 적용했다. [최종 실행 확인](evidence/experience-live-runtime.json)에 네 화면의 데스크톱·모바일 연결 상태를 기록했다.

### 고객 입력에 따른 사이즈 비교 보완

기존 프로필 카드는 준비된 66 안내와 상품 전체 리뷰만 보여주었다. `app/size_profile.py`에 고객 입력을 받아 설명 가능한 실측 비교를 수행하는 함수를 추가했다. 평소 사이즈를 기본으로 하되, 잘 맞는 **보유 의류**의 가슴단면을 입력하면 상품의 42.5/45/47.5/50cm와 비교해 같거나 큰 최소 옵션을 찾는다. 이는 신체 가슴둘레 입력이나 추정이 아니다.

반사이즈는 상품의 크게 주문 안내에 따라 평소 사이즈보다 한 단계 위를 최소 기준으로 삼는다. 보유 의류 실측과 여유 있는 핏을 함께 입력하면 실측 비교 기준보다 한 단계 큰 옵션을 고르는 **데모 규칙**을 명시한다. 두 규칙은 중복 가산하지 않는다. 키는 총길이를 확인하는 참고 정보로만 사용하며 키만으로 사이즈를 바꾸지 않는다. 필요한 옵션이 최대 88을 넘으면 추천을 만들지 않고 직접 실측 확인을 안내한다.

리뷰 근거는 해당 상품 전체 사이즈 응답의 87%, 1,046/1,202건이다. 상품 전체 리뷰 수 1,200건을 이 분모로 대체하지 않으며, 같은 체형 고객의 만족률이나 실제 맞음새 보장으로 표시하지 않는다. 프로필 기본값을 그대로 사용한 결과는 `가상프로필 · 준비 안내`, 입력값을 바꾼 결과는 `입력 기준 · 실측 비교 데모`로 구분한다. 모듈 단위 검사에 이어 새 고객 화면·개인 상태 연결도 실제 브라우저 22개 검사로 확인했다.

프로필 저장은 공개 집계에 입력값을 보내지 않고 `PROFILE_UPDATE` 행동 1건만 기록한다. 따라서 전체 행동 건수와 실제 행동 참여 고객 분모는 증가할 수 있다. 별도 HTTP 감사에서 저장 후 시청자·댓글·질문·관심·APP 상태는 그대로이고, Need를 감지시키지 않으며, 다른 고객의 프로필 및 추천도 바뀌지 않는 것을 확인했다. 공개 payload에는 키·평소 사이즈·보유 의류 실측·개별 추천이 없다.

### 실시간 모니터링부터 효과 분석까지의 연동 판정

| 구좌 | 데이터 성격과 연동 판정 |
|---|---|
| 공통 상태·카운터 | 현재 실행/방송/상품 기준 서버 상태. 고객 행동과 시연 이벤트를 구분하며, 다른 상품의 행동은 메인 상품 집계에 섞이지 않음. LIVE 시계는 도메인 가상 시계 |
| 시청 고객·연결된 고객 화면 | 실제 heartbeat의 고유 고객/탭, 선택 옵션·현재 화면·최근 수신 행동. 다중 탭 퇴장, 접속 만료, 복구 반영. 통신 실패는 미접속 대신 알 수 없음으로 표시 |
| 기존 Need 그래프·급증·대응 추천 | 실제 UI와 시연 이벤트에 같은 확정 Need 규칙을 적용한 서버 집계. 분석 tick/분석 시점의 결과를 표시하며 준비된 문구·규칙 자체는 고정. 누적 감지와 분석 스냅샷은 갱신 시점이 다름 |
| 관심 시계열·TOP 5·인사이트 | 실제 고객 질문의 서버 수신 시각과 정규화 분류. 30분/5분 경계를 적용하며 개인 질문 원문은 전송하지 않음 |
| 댓글·행동 분석 | 명시적인 공개 댓글과 실제 UI 이벤트·요청·선택·SKU·상태. 새로고침/heartbeat를 사용 횟수로 중복 가산하지 않음. 최신 행동은 ASK 직후의 자동 AI 제안 노출로 바뀔 수 있음 |
| 액션 적용·이력 | 실제 서버 승인/전달/만료/노출 확인 및 로그 수신 순서. 승인 대상 수와 실제 노출 고객 수를 구분. UI/시연/제어 동작의 출처를 표시 |
| 실제 효과 분석 | 승인 시점의 수신 순서로 나눈 누적 행동. 사이즈 질문·상세 조회·구매 체험 완료율과 기존 4개 실제 이용 지표를 별도로 표시. 완료율은 각 구간 고유 참여 고객 기준이며 인과적 성과/실제 결제가 아님 |
| 고정 결과 Simulation | 질문 26→11, 사이즈 이용 14→43, 구매 클릭 82→95는 준비된 시연값. 실제 고객 데이터나 인과 성과로 해석하지 않음. 공개해도 실제 누적 지표를 덮어쓰지 않음 |

8793 독립 서버에서 고객 컨텍스트 12개, 화면 간 연동 31개, 연결된 고객 25개, 실패/전환 경계 21개, 대시보드 전체 구좌 46개를 순차 재검증했다. 별도 8788 서버에서 신규 Director 경험 21개도 재검증했다. 모두 PASS이며, 확인한 구좌에서 누락된 고객 데이터 연동은 발견하지 않았다. 연결된 고객 검사의 일시적인 최신 행동 가정은 ASK 수신 후 자동 제안 노출을 허용하면서 실제 서버 최신 행동·건수와 비교하도록 보강했다.

## 증거와 실행 범위

- [Customer 브라우저 결과](evidence/customer-experience-verification.json) 및 [검사 코드](../scripts/check_customer_experience.cjs): 50개 PASS. 실제 버튼, 다중 탭, 오류 응답 재시도, 옵션/수량/합계, 공개·개인 데이터 분리 등을 검사한다.
- [개인 사이즈 브라우저 결과](evidence/size-profile-verification.json) 및 [검사 코드](../scripts/check_size_profile.cjs): 22개 PASS. 실제 프로필 폼과 개인 API, 추천과 구매 옵션 분리, 고객 간 격리·지연 응답·모바일·reset을 확인한다.
- [Director 브라우저 결과](evidence/director-experience-verification.json) 및 [검사 코드](../scripts/check_director_experience.cjs): 21개 검사 PASS. 별도 서버의 수신 단조 시계를 제어해 실제 브라우저 질문/HTTP/DOM 경로에서 5분·30분 경계를 확인한다. 서비스에 시험용 시간 API를 추가하지 않는다.

## 미검증 또는 의도적으로 제한한 기능

- 고객이 입력한 평소 사이즈와 보유 의류 치수를 실제 상품 실측표에 대조하는 기능을 추가했다. 실제 사람의 체형 측정이나 학습한 맞음새 모델, 비슷한 체형 고객의 만족률, 개인 후기 사진·원문 추천은 구현/검증하지 않았다. 전체 리뷰는 개인 추천의 정확도를 증명하는 수치로 사용하지 않는다.
- 영상 질의는 검수한 장면 및 샘플 제작 대본 범위다. 임의 실시간 방송 전체를 자동 전사·이해하는 기능, ASR 초안 정확도, 외부 생성형 모델의 일반적 영상 이해를 검증한 것이 아니다.
- 실제 결제·재고 예약·카드 혜택 조회·배송·쇼호스트 외부 송출은 범위 밖이다. 완료율은 구매 **체험** 지표다.
- 실제 모바일 단말, 운영 인증·권한, 서버 재시작 후 영구 저장, 대규모 동시 접속, 운영망 배포는 이 로컬 검증으로 증명하지 않는다.

첨부 이미지의 기능 영역을 로컬 프로토타입으로 확인한 결과이며, 위 제한을 실제 기능 완료로 확대해서 설명하지 않는다.
