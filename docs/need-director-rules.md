# 고객 Need와 Director 연결 규칙 — 프로토타입 결정본

이 문서는 원문 Handoff §18–26에서 정하지 않은 집계·승인·노출 규칙을 이번 작업에서 보완한 결정본이다. 시간과 임계값은 재현 가능한 데모를 위한 선택이며 실서비스에서 검증한 최적값이 아니다. 원문의 ‘30초 내 동일 Need 이벤트 2개’와 ‘동일 LIVE에서 거절한 Need 재노출 금지’를 유지한다.

## 1. 이벤트 계약과 시계

| 필드 | 의미 |
|---|---|
| `event_id` | 이벤트 1건의 고유 ID. 재전송 시 같은 ID를 사용한다. |
| `customer_id` | 데모 가상 고객 ID. 다른 고객과 공유하지 않는다. |
| `broadcast_id` | LIVE 세션 ID. 재시연 초기화 시 새 세션 상태를 사용한다. |
| `product_id` | 해당 행동이 향한 상품 ID. 문자열로 저장한다. |
| `event_type` | 원문 §18의 이벤트 이름 |
| `intent` | 질문일 때 분류한 의미. SIZE 관련은 `SIZE_GUIDANCE`. |
| `need` | 선제 제안 수락·거절일 때 `SIZE` 등 대상 Need |
| `server_received_at` | 수신 서버가 부여하는 단조 증가 시각. Reference에서는 `ingest(event, now)`의 `now`에 해당한다. |

클라이언트가 보낸 시각은 집계 기준으로 사용하지 않는다. 실제 서버 연결 시 서버가 수신 시각을 지정한다. 데모 Fixture의 `at`는 데모 실행기가 부여하는 가상 서버 시각이며 사용자 입력 타임스탬프가 아니다. 브라우저에서 임의 시간을 넣어 실제 서버 판단을 바꾸는 기능을 만들지 않는다.

같은 `event_id`의 재전송은 최초 1회만 처리한다. 다른 내용을 같은 ID로 전송하면 잘못된 이벤트로 처리한다. 이번 reference는 한 실행 동안 모든 처리 ID를 보관한다. 운영용 영구 저장소·인증·로그 수명 관리는 이 샘플의 범위가 아니다.

## 2. 개인 SIZE Need

집계 키는 `(고객, 방송, 상품, Need)`이다. 아래 서로 다른 신호 유형 중 2개가 30초 이내에 있어야 한다. 정확히 30초 차이는 포함한다.

| 이벤트 | 조건 | 신호 유형 |
|---|---|---|
| `SIZE_TAB_OPEN` | 해당 상품 사이즈 탭 열기 | 사이즈표 |
| `REVIEW_SIZE_VIEW` | 해당 상품 사이즈 리뷰 보기 | 사이즈 리뷰 |
| `ASK_LIVE_SUBMIT` | `intent=SIZE_GUIDANCE` | 사이즈 질문 |

사이즈표만 두 번 여는 것은 1종이다. 같은 질문을 반복하는 것도 1종이다. 색상 질문, Quick Action 자체 클릭, 구매 클릭은 SIZE Need 신호에 포함하지 않는다. 다른 고객·방송·상품의 이벤트끼리 합치지 않는다.

개인 Need는 이 데모에서 고객·방송·상품별 처음 한 번만 감지한다. 이후 행동으로 새 감지 인원을 늘리거나 감지 시각을 갱신하지 않는다. 이는 한 고객의 반복 행동이 집단 경고나 승인 대상 유효 시간을 계속 연장하지 않게 하기 위한 데모 규칙이다.

`SIZE_GUIDANCE`는 고객의 입력을 `내 사이즈` Direct Result로 연결하는 라우팅 분류이다. 기존 P0 ASK LIVE의 후기·두께·색상·배송 4종에 새 범용 답변 기능을 추가한다는 의미가 아니다. 원문 §24 대표 질문도 데이터에 근거가 있는 내용만 답하고, 모델 착용 사이즈 등 영상 검증이 필요한 답은 확인되지 않았다고 안내한다.

## 3. 선제 제안과 거절

개인 Need를 처음 감지하면 작은 제안을 표시한다. 자동으로 결과 화면을 열지 않는다.

- `확인하기`: `AI_SUGGESTION_ACCEPT`, `need=SIZE` 기록 → 제안을 닫고 Size Result로 이동한다.
- `괜찮아요`: `AI_SUGGESTION_DISMISS`, `need=SIZE` 기록 → 동일 방송에서 같은 Need의 선제 제안을 다시 표시하지 않는다.
- 수동 `내 사이즈` 진입은 수락·거절·승인·만료와 관계없이 허용한다.

거절 키는 `(고객, 방송, Need)`이다. 같은 방송에서 상품을 바꿔도 SIZE 거절은 유지한다. 새 방송에서는 별개다. 거절을 개인 Need 신호 자체의 삭제로 취급하지 않으므로 집단 관심 통계에는 기존 감지가 남는다.

## 4. 집단 Spike — 8 → 26의 의미를 확정

원문 §24의 `Size Signal`은 단위가 지정되지 않았다. 이번 결정에서 **각 시간 구간에 처음 SIZE Need가 감지된 고유 고객 수**로 정의한다. 질문 건수·클릭 횟수와 혼용하지 않는다. UI는 `사이즈 관심 감지 고객 8명 → 26명`처럼 단위를 표시한다.

동일 방송·상품별로 분석 시각 `t`에 다음을 비교한다.

- 직전 구간: `(t−120초, t−60초]`
- 현재 구간: `(t−60초, t]`
- 분석 주기: 가상 LIVE 시작부터 60초마다. 이벤트를 받을 때마다 집단 경고를 계산하지 않는다.
- 발생 조건: 현재 10명 이상이면서, 직전의 2배 이상.
- 직전 0명: 현재 10명 이상이면 경고한다. 증가율은 `신규 증가`로 표시하고 나누기 0이나 무한대 비율은 표시하지 않는다.

현재 수치 자체가 고유 고객 수이므로 별도의 ‘최소 고객 5명’ 조건을 중복해 두지 않는다. 8→26이면 `(26−8)/8×100 = +225%`이다.

같은 고객이 이벤트를 100번 발생시켜도 새로운 개인 Need 감지는 최대 1명이다. 이 데모는 상품별 한 차례의 `NORMAL → ALERT → ACTION → RESULT`를 지원한다. 동일 시나리오에서 같은 경고를 반복 생성하지 않으며, 다시 시연하려면 전체 데모 상태를 초기화한다.

설명 문구는 관찰 가능한 신호에 맞춘다.

> 최근 60초 동안 사이즈 관련 행동이 함께 나타난 고객이 8명에서 26명으로 증가했습니다. 평소 사이즈와 반사이즈 선택 기준을 안내하는 대응을 제안합니다.

사이즈 고민 때문에 실제 구매를 못 한다거나, 가격·상품 만족에는 문제가 없다고 단정하지 않는다. 대표 질문은 실제 입력 근거 또는 `예시 질문`이라고 표시한 Fixture 문구를 사용한다.

## 5. PD 승인과 고객 화면

개인 Need 제안은 고객별 자동 반응이고, PD 승인은 집단 경고 후 `내 사이즈` Quick Action을 강조하는 별도 동작이다. **PD 승인에 의해 팝업·결과 화면·새 제안을 자동으로 띄우지 않는다.** 승인 이전에도 개인 Need 제안은 표시될 수 있다. 승인 전후 검수에서 확인하는 항목은 이 버튼 강조다.

승인 시점에 다음 조건을 모두 만족하는 고객 목록을 한 번 저장한다.

1. 승인 대상과 같은 방송·상품에서 개인 SIZE Need가 감지됨.
2. 감지 시각이 `(승인 시각−120초, 승인 시각]`에 있음.
3. 동일 방송에서 SIZE 제안을 거절하지 않음.
4. 현재 보고 있는 상품이 확인되는 경우 승인 상품과 같음.

이 snapshot은 승인 후 감지된 고객으로 자동 확대하지 않는다. 승인 요청 ID를 재사용하거나 버튼을 다시 눌러도 같은 승인 결과를 반환한다. 대상 목록·유효 기간을 재생성하지 않는다. 다른 상품의 승인에 같은 요청 ID를 쓰면 오류다.

표시 방식:

- 고객에게 익숙한 위치의 `내 사이즈` 버튼 순서는 유지한다.
- 대상 고객의 해당 버튼에 테두리 강조와 작은 `추천` 표시를 추가한다.
- 클릭하면 기존 Size Result로 이동한다.
- 유효 기간은 승인 시각부터 300초 미만이다. 정확히 300초 경과 시 강조가 사라진다.
- 방송 종료, 상품 전환, SIZE 제안 거절 중 먼저 발생한 조건에도 강조를 해제한다.
- 상품을 되돌려도 기존 강조는 자동 복구하지 않는다.
- 비대상 고객의 버튼은 기본 표시를 유지한다.

방송 종료는 UI/서버가 세션을 종료하고 해당 LIVE 상태를 폐기하는 동작이다. Reference에는 상품 전환 API가 있고 세션 초기화는 새 `NeedDirector` 인스턴스로 수행한다.

거절이 승인보다 우선이다. 승인 전에 거절한 고객은 대상에서 제외하고, 승인 후 거절한 고객도 즉시 강조를 해제한다. 이때도 수동 `내 사이즈`는 사용할 수 있다.

## 6. Director 상태와 쇼호스트 동작

| 상태 | 진입 조건 | 고객 영향 |
|---|---|---|
| NORMAL | 초기화 | PD 개인화 없음 |
| ALERT | 집단 Spike 조건 충족 | PD 개인화 없음 |
| ACTION | PD가 APP 승인 또는 쇼호스트 전달 실행 | APP 승인 때만 대상 버튼 강조 |
| RESULT | APP 승인 후 가상 30초 경과, 준비된 결과 표시 실행 | 강조 TTL은 계속 적용 |

쇼호스트 전달은 외부 메시지를 보내지 않는 로컬 완료 표시다. 재클릭은 같은 완료 상태를 유지한다. 쇼호스트 전달만 실행해도 APP 개인화를 승인한 것으로 간주하지 않는다. Bookmark·영상 AI는 이 흐름에 의존하지 않는다.

## 7. 결과 수치는 별도 Simulation

`director-scenario.json`의 `result_metrics`는 원문 §26의 예시를 채택한 설명용 비교 값이다. 각 값은 사전 작성된 전후 60초 스냅샷으로 표시하고 `Prototype Simulation`을 계속 표시한다. 위 개인 Need 이벤트에서 계산한 실제 결과가 아니다. 승인 후 가상 30초에 표시하는 것은 발표용 재생 일정이며, 그때 실제 60초 측정이 완료됐다는 뜻이 아니다.

| 항목 | 전 → 후 | 정수 반올림 증감률 |
|---|---|---|
| 사이즈 반복 질문 건수 | 26 → 11 | −58% |
| 내 사이즈 이용 건수 | 14 → 43 | +207% |
| 구매하기 클릭 건수 | 82 → 95 | +16% |

ALERT의 26은 고유 고객 수이고, RESULT의 26은 준비된 반복 질문 건수다. 우연히 숫자가 같아도 같은 지표가 아니다. 이 값으로 실제 매출·구매 전환·인과 효과를 검증했다고 설명하지 않는다.

## 8. 재현 시나리오와 실행

Fixture의 방송은 `GS-LIVE-DEMO-001`, 상품은 `1084192893`이다. 전체 이벤트가 가상 데이터다.

| 가상 시각 | 입력·결과 |
|---|---|
| 0–60초 | 8명의 서로 다른 고객에게 SIZE Need 감지. 고객 B는 색상만 질문. |
| 60–120초 | A·C와 기타 24명, 총 26명의 신규 SIZE Need 감지. C는 제안을 거절. |
| 120초 분석 | 직전 8, 현재 26, +225%, ALERT |
| 121초 승인 | 최근 120초 감지 34명 중 C를 제외한 33명 snapshot. A 포함, B·C 제외. |
| 151초 결과 | 준비된 Simulation 결과로 RESULT 전환 |
| 421초 | 121초 승인으로 시작한 강조 TTL 만료 |

실행은 네트워크·외부 패키지·실제 대기 없이 가상 시계로 이루어진다. Python 3.9 이상에서 다음을 실행한다.

```sh
python3 prototype/need_director.py
python3 -m unittest discover -s tests -p 'test_need_director.py' -v
```

Demo Control은 이 Fixture를 순서대로 재생하고 분석 시계를 진행시킨다. UI 경고만 강제로 바꾸고 입력 없는 근거를 붙이는 방식으로 구현하지 않는다. 초기화 시 이벤트 ID, 개인 감지, 거절, 경고, 승인, 결과, 가상 시계를 함께 초기화한다. 사용자 프로필·정적 상품·코디 자료는 유지해도 된다.

## 9. 검수 범위

자동 테스트는 고객 A 적용/B·C 미적용, 8→26 집계, 동일 행동 반복, 다른 고객·상품·방송 분리, 30초와 60초 경계, 중복 이벤트, 증가율 조건, 승인 snapshot·중복 승인·만료, 거절 우선, 상품 전환, 쇼호스트 독립 동작, 결과 Simulation 표시, 시계 역행 방지를 검증한다.

이 결과는 로직과 Fixture 검증이다. 브라우저에서 버튼 테두리·추천 표시, 세로/가로 화면, 결과 페이지 이동을 확인한 UI 검수 결과는 아니다. 실제 UI 구현 시 같은 Fixture와 기대값으로 해당 화면을 추가 검수한다.
