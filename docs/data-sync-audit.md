# Director ↔ Mobile 데이터 연동 검수

2026-09-22. 단순히 이벤트가 저장되는지뿐 아니라 반대편의 실제 화면에 표시되는지 확인했습니다.

## 확인한 누락과 보완

|흐름|기존 상태|보완 후 확인 위치|

|결과·만료 → Mobile|강조 스타일만 변경|이용 안내에 결과 확인/강조 만료 상태 표시. Director가 닫혀도 Mobile이 만료 처리, 중복 만료 이벤트 차단|

## 저장과 데이터 구분

- 원본 상태: 같은 origin의 IndexedDB `gs-ai-live-shared` / `state` / `current`.
- 화면 알림: BroadcastChannel, 보조 storage 알림. localStorage 키 `gs-ai-live:shared-state:v1`은 기존 상태 이관과 호환용 미러입니다. 기존 상태를 임의로 초기화하지 않습니다.
- 동시 변경: IndexedDB 트랜잭션으로 원자적 업데이트. 지원 환경에서는 Web Locks로 발행 순서도 정렬합니다. 오래된 방송 ID로 들어온 작업과 늦은 리비전 알림은 현재 방송을 덮어쓰지 않습니다.
- IndexedDB를 사용할 수 없으면 기존 저장소/메모리 방식으로 기능을 유지하되 화면에 동시 쓰기 보장이 지원되지 않음을 표시합니다. 모든 저장소가 차단되면 탭 간 연동은 불가능합니다.
- Mobile의 입력 중인 질문·대화·장바구니 편집 상태·영상 DOM은 탭 소유입니다. Director 고객 A 상태는 **가장 최근 이벤트를 보낸 Mobile 탭의 스냅샷**입니다. 여러 Mobile 창을 열면 마지막 수신 탭 기준이며 실제 복수 고객 기능이 아닙니다.
- Mobile을 새로고침하면 탭 내부 대화/장바구니는 초기화되고 그 현재 상태를 Director에 다시 보냅니다. 방송의 누적 이벤트/승인/거절은 유지됩니다. 공통 Reset은 방송 단위 누적값을 초기화합니다.
- 새 기능별 이용 집계는 이번 연동 코드가 수집한 이벤트부터 정확히 계산합니다. 이전 버전에 없던 이용 수를 임의로 만들어 소급하지 않습니다. 반복 시연은 공통 Reset 후 확인하세요.
- 질문 집계는 실제 UI 입력 유형 기준입니다. 자유 질문 원문·작성 중 초안은 공유 저장소에 넣지 않습니다.
- 실제 기능 이용/구매 체험 수와 8→26, 대상33, 주문86/전환율3.2%, 결과26→11 등의 **고정 Simulation**은 별개입니다. 구매 체험 금액은 실제 결제나 매출이 아닙니다.

## 검증

2026-09-22 최종 수정본에서 아래 6개 명령을 모두 통과했습니다. 공통 상태 단위 검사 9건, 고객 UI Reset 3회 연속 재현, 실제 30초 만료, 거절 후 새로고침 유지, 동시 입력 80건 보존을 포함합니다. 브라우저 검수는 격리된 Chrome 프로필에서 수행했으며 실기기 검수는 포함하지 않습니다.

서버 실행 후 브라우저 명령은 순서대로 실행하세요.

```bash
npm test
npm run verify
npm run test:sync
npm run test:features
npm run test:browser
npm run test:video
```

`test:sync`는 실제 포인터 클릭으로 두 화면을 조작합니다. 선택77/데일리, 기능 이용, 장바구니 수량/삭제, 단품+장바구니 구매 체험, 실제 영상 이벤트, 승인 문구/미리보기, 승인 후 증가분, Director 종료 후 실제30초 만료, 답변 대기 중 Reset을 검증합니다. 동시성 스트레스 부분만 reducer API로 두 탭에서 40건씩 제출하여 80건 보존을 검증합니다.

비동기 저장 완료는 방송 ID 변경, 승인 상태와 모달 닫힘, 제안 숨김으로 확인합니다. 클릭 직후 저장 완료를 기다리지 않고 페이지를 닫는 경우까지 보장하지는 않습니다.

추가 재현 검사: `node scripts/sync-stress.test.mjs`. 동시 입력 직후와 알림 처리 후 양쪽 저장값·리비전·화면을 비교합니다. 초기 localStorage 전용 방식에서 80건 중 일부가 손실됐고 트랜잭션 적용 후 80건이 유지됨을 확인했습니다.

## 범위 밖

다른 브라우저/기기/서버 간 동기화, 실서비스 인증/고객 구분, 실주문/결제/재고, 실제 방송 송출·쇼호스트 전송, 최신 상품/혜택 API는 연결하지 않았습니다. `localhost`와 `127.0.0.1`, 다른 포트도 다른 origin입니다. 두 화면 모두 동일한 시작 주소에서 열어야 합니다. 기존에 열어둔 두 탭을 모두 새로고침해 같은 버전의 코드를 사용하세요.
