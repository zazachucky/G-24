5. Customer–Director 공통 상태와 확정 규칙

고객 화면과 Director가 같은 실행·방송·상품의 공통 상태를 사용하게 한다. 실제 UI 이벤트와 시연 이벤트는 출처를 구분하되 같은 도메인 처리 경로를 통과시킨다. Need·승인·대상 선정·TTL은 결정적 로직으로 처리한다.

- 개인 Need: 같은 고객·방송·상품에서 사이즈표·사이즈 리뷰·사이즈 질문 중 서로 다른 2종이 30초 이내 발생할 때 최초 한 번 감지한다. 정확히 30초는 포함하며 event_id 중복과 같은 행동 반복으로 인원을 늘리지 않는다.
- 선제 제안: 확인하기/괜찮아요를 제공한다. 수락 전 결과를 강제로 열지 않는다. 거절한 같은 LIVE·Need는 다시 제안하지 않으며 수동 내 사이즈 접근은 유지한다.
- Spike: 직전/현재 각 60초의 신규 감지 고유 고객 수를 비교한다. 현재 10명 이상이고 직전의 2배 이상이면 ALERT다. 직전 0명은 확정 규칙대로 처리한다.
- Director: 모니터링·근거·추천안·액션 기록·결과를 연결한다. 쇼호스트 전달 문구를 검토·수정하고, APP 대상·제외 사유·미리보기를 확인한 뒤 각 Action을 독립적으로 승인한다. 쇼호스트 전달은 로컬 Simulation이다.
- APP 승인: 승인 시 최근 120초 내 관련 고객에서 거절 고객 등을 제외해 대상을 고정한다. PD 승인에 따른 고객 버튼 강조는 승인 전 적용하지 않고, 승인 후 대상의 기존 내 사이즈 버튼에만 테두리와 추천 표시를 적용한다. 팝업이나 결과를 자동으로 열지 않는다.
- 강조: 승인 후 300초 미만 유지한다. 거절·상품 전환·방송 종료 시 먼저 해제하며, 재승인으로 대상·기간을 늘리지 않는다. 상품을 되돌려도 자동 복구하지 않는다.
- 확정 시나리오: 120초에 8→26명(+225%), 121초 APP 승인 대상 33명(A 포함, B/C 제외), 151초 결과, 421초 강조 만료를 재현한다.
- 결과: 질문 26→11(-58%), 내 사이즈 이용 14→43(+207%), 구매 클릭 82→95(+16%)의 고정 Simulation이다. 실제 매출 효과나 이벤트에서 계산한 실측 결과로 설명하지 않는다.
- Demo Control: Start Need Demo는 68초까지, Trigger Director Spike는 미처리 이벤트만 120초까지 이어 재생한다. Reset은 이벤트·거절·승인·강조·결과·시계·이전 요청을 함께 초기화한다. 강제 상태 전환으로 정상 경로 검수를 대체하지 않는다.

6. 제공 MP4의 참고 재생

상품 이미지 기반 기본 모드를 유지하면서 첨부 MP4의 기본 재생을 앱에 연결하고 검수한다. 이 영상은 현재 상품과 다른 코어어센틱 가디건이므로 `녹화 참고 영상 · 코어어센틱 가디건 · 현재 상품과 다름`을 표시한다. 기존 120초 테스트 영상과 구분하고 원본 파일·해시·앱 내부 경로를 기록한다. 실행 코드에 개인 Downloads 절대 경로를 넣지 않는다.

재생·정지·음소거/음량·탐색·종료·오류를 처리하고 실제 duration을 사용한다. 원본 9:16을 비율 유지로 표시하며 화면 전환 후 재생 위치와 상태를 보존한다. 영상 시계와 Need/승인 가상 시계를 분리한다. 파일·코덱·음성 오류 시 안내와 상품 이미지 대체를 제공하고 비영상 흐름을 유지한다.

전사·장면 검색·요약·Catch-up·영상 ASK LIVE는 기능별 검증 전까지 TODO/비활성 상태로 둔다. 영상 속 상품·발화·착용 정보를 SJ와니 상품의 근거로 사용하지 않는다. 미검증 타임코드나 발화를 생성하지 않는다. 이번 목표는 새로운 쇼호스트 영상 제작을 포함하지 않는다.
